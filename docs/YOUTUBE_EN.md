# 英語の解説・雑学動画を作る

このPC内のMoneyPrinterTurbo-Foundationを使う。入口は `youtube-en.cmd`。制作前の品質監査や承認待ちを挟まず、指定した題材から制作へ進む。

## 3言語を同時に作る

画面上部の **3 languages: English / Hindi / Spanish** は初期値オン。元の台本を用意したあと、英語・ヒンディー語・スペイン語へ分け、翻訳・音声・字幕を3件並行で作る。動画素材は1回用意して共用し、PCで重い書き出しは1本ずつ行う。各言語の実音声から字幕時刻を作り、映像もその言語の音声の長さに合わせる。

翻訳には **Configure LLM** で設定したモデルを使う。原文の言語が出力先と一致する場合は翻訳しない。翻訳済み台本はAPI/設定JSONの `language_scripts` に `en`・`hi`・`es` を指定すればモデルへの要求を省ける。1言語が失敗しても他の言語は進め、できた音声・字幕・動画を保持する。

完成欄には言語名と、動画・音声・SRT字幕のダウンロードを表示する。保存先は `storage/tasks/<元のID>-en`・`-hi`・`-es`。元のIDのフォルダに `languages.json` を保存する。3言語の自動投稿は行わない。元の音声ファイルをそのまま別言語用には流用せず、それぞれの言語で合成する。

選定根拠は [2025年の公開研究](https://journals.sagepub.com/doi/10.1177/20563051251363216)。2022年末の動画数の推定で英語・ヒンディー語・スペイン語が上位3言語。現在の視聴時間や収益の上位3を保証するものではない。

APIの音声・字幕・動画要求では `multilingual_enabled: true` で有効化する。APIは既存利用との互換性のため初期値オフ。画面のチェックを外すと従来の1言語制作に戻せる。

ヒンディー語にはOFLのNoto Sans Devanagariを同梱し、このPCのFFmpegの字幕描画を使う。通常の文字描画だけでは文字のつながりが崩れるWindows環境に対応した。ヒンディー語の焼き込みは下部・文単位の表示を出発点とする。

3言語の実音声・SRT字幕・字幕付き動画を作成済み。作例の保存先は `C:\Users\nyu17\yu-lab\media\projects\youtube-three-languages-20261101`。作例は用意済み翻訳を使用し、有料モデルの翻訳要求は行っていない。音声3件が同時に開始し、それぞれ1要求で完了した記録を残した。

## 起動と接続

1. エクスプローラーで `C:\Users\nyu17\yu-lab\repos\MoneyPrinterTurbo-Foundation` を開く。
2. `youtube-en.cmd` をダブルクリックする。
3. 表示された `http://127.0.0.1:8501` を開く。使用中の場合は起動窓に別の番号が出る。
4. 初回のモデル設定は、題材欄の横の **Configure LLM** を押し、利用するProvider・Model・API Keyを設定する。**Test LLM Connection** は設定を変えた時の任意の接続確認で、毎回の制作条件にはしない。

初回だけ英語用の設定を適用する。その後に利用者が変更した台本・音声などの設定は、次回起動時にも維持する。APIキーと選択モデルは初期設定処理で変更しない。別のフォルダから起動しても、このリポジトリのPythonを使う。

モデル・素材サービスの認証情報は、この作業では追加していない。Pexelsを使う場合はそのキー、手持ち素材を使う場合は素材ファイルが必要。

用意済みの英文を使うなら **Video Script** に貼り、**Video Source** で **Local file** を選び、**Upload Local Files** に画像・動画を追加して **Generate Video** を押す。英語1言語でモデル用キーを使わない場合は **3 languages** のチェックを外す。3言語で自動翻訳する場合はモデル設定が必要。音声の生成にはインターネット接続を使う。

## 出発点

| 項目 | 初期設定・目安 |
|---|---|
| 言語 | 英語 en-US。題材名を日本語で入力しても英語を指定する |
| 内容 | 一つの問い → 仕組み → 身近な例 → 一つの持ち帰り |
| 縦型の短い動画 | 45〜75秒、100〜160語程度を出発点にする |
| 長い解説 | 3〜5分、400〜750語程度を出発点にする |
| 音声 | en-US-GuyNeural、話速1.0。Edge系の時刻情報で字幕を作る |
| 素材 | 台本に沿った検索語の順序を保つ。重い意味解析モデルは追加しない |
| 描画 | CPU。素材処理は1件ずつ。完成動画もまず1本ずつ |
| BGM | 初期値はオフ。使いたい手持ち音源を指定した時に追加する |

秒数・語数・段落数・画質は目標であり、達しないだけで停止・水増し・作り直しを行わない。実尺は音声で決まる。**Advanced Script Settings** の追加指示で、作りたい長さや語り口を変更できる。

短い動画と長い動画を混在させるより、まず一つの題材・語り口で作り始める。これは運用上の提案で、制作を止める条件ではない。

## 今回整理した動作

- 台本・検索語・投稿用情報は、それぞれ1回の生成要求で扱う。同じ生成を最大5回繰り返すループの予算を1回にした。OpenAI互換・Gemini・LiteLLMの本経路ではSDKの自動再送も無効化する。
- 上記の生成要求は90秒を初期タイムアウトとした。遅いローカルモデル等を選ぶ場合は、非公開のconfig.tomlの `[app].llm_request_timeout_seconds` を調整できる。これは通信待ちの上限で、動画の品質基準ではない。Claude Code等の別接続経路には個別のタイムアウトもある。
- 接続確認用の待ち時間は10秒。失敗後にモデル・キー・サービスを勝手に切り替えない。
- 初期音声のEdge合成も1回。音声ができて字幕時刻だけない場合は、音声を捨てて再合成せず、字幕なしで続ける。
- 480ピクセル未満という理由だけで、読み込めるローカル素材や検索素材を除外しない。0サイズや読めないファイルなど、処理できない実データは使えない理由を残す。
- 明示した英語指定を題材の言語より優先する。段落数は目安とプロンプトに明記し、返った本文を段落数に合わせて切り落とさない。
- 既存の音声試聴の再利用、素材検索の保存、途中成果物、完成済みの出力は保持する。任意の字幕が用意できない場合の既存の継続経路も残す。
- GitHub上の全件検査・書式検査・検査率70％必須を外し、Windowsの小さな確認を手動実行だけにした。起動・制作の必須工程にはしない。GitHubへは未反映。

生成が通信障害で失敗した時の手動再実行はできる。失敗した処理を成功と記録したり、使えない認証や不存在の素材をあることにしたりしない。

## 実装の見取り図

`WebUI / CLI / API → task.py → 台本 → 検索語 → 音声 → 字幕 → 素材 → 映像・音声結合 → 保存`

| 場所 | 担当 |
|---|---|
| `webui/Main.py` / `webui.bat` | 設定と操作画面・Windowsの起動 |
| `cli.py` / `app/controllers/v1` | コマンドとAPIの入口 |
| `app/services/task.py` | 各工程と途中成果の受け渡し |
| `app/services/llm.py` | 台本・検索語・投稿用情報。追加の査読モデルは呼ばない |
| `app/services/voice.py` / `subtitle.py` | 音声と実音声由来の字幕時刻 |
| `app/services/material.py` / `material_cache.py` | 素材の取得と検索結果の再利用 |
| `app/services/video.py` | 素材の変換・結合・字幕と音声の出力 |
| `app/services/video_project.py` | 既存音声・映像を受け取る別の編集版管理CLI |

通常の制作に `doctor` やテスト一式を追加しない。`video_project.py` の編集版管理や外部投稿も、使わない限り通常制作の必須工程にしない。
